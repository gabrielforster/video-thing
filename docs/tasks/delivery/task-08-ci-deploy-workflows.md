**Files:**
- Create: `.github/workflows/ci.yml`
- Create: `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: `Makefile` target `images`; `scripts/image-smoke.sh`; `scripts/run-migrations.sh`; the environment outputs `ecs_cluster_name`, `private_subnet_ids`, `migrations_task_definition_family`, `migrations_security_group_id`, `migrations_log_group_name`, `web_bucket_id`, `cloudfront_distribution_id`, `app_url`; the role from Task 6.
- Produces: `ci.yml` (four independent jobs, no AWS credentials, runs on every push and PR) and `deploy.yml` (one job, `workflow_dispatch` only).

**Repository configuration this needs.** Repository *variables*, under Settings → Secrets and variables → Actions → Variables:

| Name | Value | Confidential? |
|---|---|---|
| `AWS_ROLE_ARN` | printed by `scripts/bootstrap-aws.sh` | no — an ARN is not a credential; the trust policy is what restricts who may assume it |
| `AWS_REGION` | e.g. `us-east-1` | no |

Repository *secrets*: **none**. That is the point of OIDC. The database password is generated by `random_password` inside Terraform, written to Secrets Manager, and read by the ECS agent using the task execution role — it is never an input to a workflow, never printed, and never in an image layer. Terraform state does contain it in plaintext, which is why the state bucket is private, versioned, and SSE-encrypted (Task 6) and why `.gitignore` already excludes `*.tfstate`.

Also create three GitHub Environments named `dev`, `staging`, and `production` (Settings → Environments) — the trust policy from Task 6 keys on the environment name, so a deploy to an environment that does not exist fails at role assumption. Put required reviewers on `production`.

**Why `workflow_dispatch` only.** A push-triggered apply against an environment whose idle cost is ~$74/month, in a repository where the infrastructure has never been applied, is a footgun. The trigger is manual and per-environment on purpose. Adding `push: branches: [master]` limited to `dev` is a three-line change once someone has decided to pay for a permanent dev environment; the plan does not make that decision for them.

- [ ] **Step 1: Write `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  push:
    branches: [master]
  pull_request:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  go:
    name: Go
    runs-on: ubuntu-24.04
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_DB: videothing
          POSTGRES_USER: user
          POSTGRES_PASSWORD: userpassword
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U user -d videothing"
          --health-interval 5s
          --health-timeout 5s
          --health-retries 10
    env:
      DATABASE_URL: postgres://user:userpassword@localhost:5432/videothing?sslmode=disable
    steps:
      - uses: actions/checkout@v7.0.1

      - uses: actions/setup-go@v7.0.0
        with:
          go-version: '1.25.5'
          cache: true

      - name: gofmt
        run: |
          unformatted="$(gofmt -l .)"
          if [ -n "$unformatted" ]; then
            echo "these files are not gofmt-clean:"
            echo "$unformatted"
            exit 1
          fi

      - name: go vet
        run: go vet ./...

      # packages/database/db's tests skip themselves without DATABASE_URL, so without a real
      # database `go test ./...` would pass while never touching a query.
      - name: install golang-migrate
        run: go install -tags 'postgres' github.com/golang-migrate/migrate/v4/cmd/migrate@v4.19.1

      - name: apply migrations
        run: migrate -path packages/database/migrations -database "$DATABASE_URL" up

      - name: go test
        run: go test ./...

  web:
    name: Web
    runs-on: ubuntu-24.04
    defaults:
      run:
        working-directory: apps/web
    steps:
      - uses: actions/checkout@v7.0.1

      - uses: pnpm/action-setup@v6.0.9
        with:
          version: 10

      - uses: actions/setup-node@v7.0.0
        with:
          node-version: '22'
          cache: pnpm
          cache-dependency-path: apps/web/pnpm-lock.yaml

      - name: pnpm install
        run: pnpm install --frozen-lockfile

      - name: pnpm lint
        run: pnpm lint

      - name: pnpm test
        run: pnpm test

      # The deployed bundle is built with VITE_API_URL empty so api.ts's relative paths
      # resolve against the CloudFront hostname the page came from. If a Vite change ever
      # drops an empty-string variable, `?? 'http://localhost:8080'` fires and the deployed
      # app silently calls localhost. Catch that here, not in production.
      - name: build with an empty VITE_API_URL and assert no localhost fallback
        env:
          VITE_API_URL: ''
        run: |
          pnpm build
          if grep -rq 'localhost:8080' dist/assets/; then
            echo "the bundle contains localhost:8080 -- the VITE_API_URL fallback fired"
            exit 1
          fi

  terraform:
    name: Terraform (${{ matrix.environment }})
    runs-on: ubuntu-24.04
    strategy:
      fail-fast: false
      matrix:
        environment: [dev, staging, production]
    steps:
      - uses: actions/checkout@v7.0.1

      - uses: hashicorp/setup-terraform@v4.0.1
        with:
          terraform_version: 1.15.8
          terraform_wrapper: false

      - name: terraform fmt
        run: terraform fmt -check -recursive
        working-directory: infrastructure/terraform

      # -backend=false: validation must not need the state bucket or AWS credentials.
      - name: terraform init
        run: terraform init -backend=false -input=false
        working-directory: infrastructure/terraform/environments/${{ matrix.environment }}

      - name: terraform validate
        run: terraform validate
        working-directory: infrastructure/terraform/environments/${{ matrix.environment }}

  images:
    name: Images
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v7.0.1

      - name: build all three images
        run: make images

      - name: smoke test the images
        run: ./scripts/image-smoke.sh
```

- [ ] **Step 3: Write `.github/workflows/deploy.yml`**

```yaml
name: Deploy

on:
  workflow_dispatch:
    inputs:
      environment:
        description: Environment to deploy to
        type: choice
        options: [dev, staging, production]
        default: dev

permissions:
  contents: read
  id-token: write

concurrency:
  group: deploy-${{ inputs.environment }}
  cancel-in-progress: false

jobs:
  deploy:
    name: Deploy to ${{ inputs.environment }}
    runs-on: ubuntu-24.04
    environment: ${{ inputs.environment }}
    defaults:
      run:
        shell: bash
    env:
      TF_ENV: ${{ inputs.environment }}
      TF_DIR: infrastructure/terraform/environments/${{ inputs.environment }}
      AWS_REGION: ${{ vars.AWS_REGION }}
      IMAGE_TAG: ${{ github.sha }}
    steps:
      - uses: actions/checkout@v7.0.1

      # The job's `environment:` above is what puts environment:<name> in the OIDC token's
      # `sub` claim, which is what the role's trust policy matches on.
      - name: Assume the deploy role via OIDC
        uses: aws-actions/configure-aws-credentials@v6.2.3
        with:
          aws-region: ${{ vars.AWS_REGION }}
          role-to-assume: ${{ vars.AWS_ROLE_ARN }}
          role-session-name: video-thing-deploy-${{ github.run_id }}

      - uses: hashicorp/setup-terraform@v4.0.1
        with:
          terraform_version: 1.15.8
          terraform_wrapper: false

      - name: terraform init
        working-directory: ${{ env.TF_DIR }}
        run: terraform init -input=false

      # The ECR repositories have to exist before anything can be pushed to them, and the
      # ECS task definitions reference image URIs that only become valid after the push.
      # This targeted apply breaks that loop; it is a no-op on every run after the first.
      - name: Ensure the ECR repositories exist
        working-directory: ${{ env.TF_DIR }}
        run: terraform apply -input=false -auto-approve -lock-timeout=5m -target=module.ecr

      - name: Log in to ECR
        id: ecr
        uses: aws-actions/amazon-ecr-login@v2.1.6

      # The repositories are IMMUTABLE, so re-running this workflow for the same SHA would
      # fail on push. Skipping an image that is already there keeps re-runs idempotent.
      - name: Build and push the api, worker, and migrations images
        env:
          REGISTRY: ${{ steps.ecr.outputs.registry }}
        run: |
          set -euo pipefail
          for name in api worker migrations; do
            repo="video-thing-$TF_ENV-$name"
            if aws ecr describe-images --repository-name "$repo" \
                 --image-ids "imageTag=$IMAGE_TAG" >/dev/null 2>&1; then
              echo "==> $repo:$IMAGE_TAG already in ECR, skipping"
              continue
            fi
            echo "==> building and pushing $repo:$IMAGE_TAG"
            docker build --platform linux/amd64 -f "docker/$name.Dockerfile" \
              -t "$REGISTRY/$repo:$IMAGE_TAG" .
            docker push "$REGISTRY/$repo:$IMAGE_TAG"
          done

      # Registers the new migrations task definition without touching the API or worker
      # services, so migrations run strictly before any new application code is rolled out
      # (video-thing-spec.md 18, database-schema.md "CI/CD integration"). The cluster is
      # targeted alongside it because run-task needs it on a first-ever deploy. Terraform
      # prints a -target warning; that is expected here, not a problem to fix.
      - name: Register the migrations task definition
        working-directory: ${{ env.TF_DIR }}
        run: |
          terraform apply -input=false -auto-approve -lock-timeout=5m \
            -target=module.migrations \
            -target=module.ecs.aws_ecs_cluster.this \
            -var "api_image_tag=$IMAGE_TAG" \
            -var "worker_image_tag=$IMAGE_TAG" \
            -var "migrations_image_tag=$IMAGE_TAG"

      - name: Run database migrations
        working-directory: ${{ env.TF_DIR }}
        run: |
          set -euo pipefail
          CLUSTER="$(terraform output -raw ecs_cluster_name)" \
          TASK_DEFINITION="$(terraform output -raw migrations_task_definition_family)" \
          SUBNETS="$(terraform output -json private_subnet_ids | jq -r 'join(",")')" \
          SECURITY_GROUPS="$(terraform output -raw migrations_security_group_id)" \
          LOG_GROUP="$(terraform output -raw migrations_log_group_name)" \
          STARTED_BY="github-${{ github.run_id }}" \
          "$GITHUB_WORKSPACE/scripts/run-migrations.sh"

      - name: terraform apply
        working-directory: ${{ env.TF_DIR }}
        run: |
          terraform apply -input=false -auto-approve -lock-timeout=5m \
            -var "api_image_tag=$IMAGE_TAG" \
            -var "worker_image_tag=$IMAGE_TAG" \
            -var "migrations_image_tag=$IMAGE_TAG"

      - name: Wait for the ECS services to reach steady state
        working-directory: ${{ env.TF_DIR }}
        run: |
          set -euo pipefail
          CLUSTER="$(terraform output -raw ecs_cluster_name)"
          aws ecs wait services-stable --cluster "$CLUSTER" \
            --services "video-thing-$TF_ENV-api" "video-thing-$TF_ENV-worker"
          aws ecs describe-services --cluster "$CLUSTER" \
            --services "video-thing-$TF_ENV-api" "video-thing-$TF_ENV-worker" \
            --query 'services[].[serviceName,runningCount,desiredCount,deployments[0].rolloutState]' \
            --output table

      - uses: pnpm/action-setup@v6.0.9
        with:
          version: 10

      - uses: actions/setup-node@v7.0.0
        with:
          node-version: '22'
          cache: pnpm
          cache-dependency-path: apps/web/pnpm-lock.yaml

      # Empty, not unset. api.ts reads `import.meta.env.VITE_API_URL ?? 'http://localhost:8080'`
      # and `??` does not fire on '', so API_URL becomes '' and every call is a root-relative
      # path served by this same distribution. The grep is the guard: if a Vite change ever
      # drops empty-string variables, the fallback fires and the deployed app calls localhost.
      - name: Build the web app against its own origin
        working-directory: apps/web
        env:
          VITE_API_URL: ''
        run: |
          set -euo pipefail
          pnpm install --frozen-lockfile
          pnpm build
          if grep -rq 'localhost:8080' dist/assets/; then
            echo "refusing to deploy: the bundle contains localhost:8080"
            exit 1
          fi

      # Two syncs, because the cache headers differ. Vite writes content-hashed filenames
      # into dist/assets, so those are safe to cache forever -- a new build produces new
      # names rather than new contents under old names. Everything else (index.html,
      # favicon.svg, icons.svg) keeps its name across builds and must never be cached, or a
      # deploy would leave browsers pointing at deleted asset hashes.
      - name: Sync the web app to S3
        working-directory: ${{ env.TF_DIR }}
        run: |
          set -euo pipefail
          BUCKET="$(terraform output -raw web_bucket_id)"
          cd "$GITHUB_WORKSPACE"
          aws s3 sync apps/web/dist/assets "s3://$BUCKET/assets" --delete \
            --cache-control "public,max-age=31536000,immutable"
          aws s3 sync apps/web/dist "s3://$BUCKET" --delete --exclude 'assets/*' \
            --cache-control "no-cache"

      # Scoped, not /*. The hashed files under /assets/ are new keys that were never cached
      # under these names, so invalidating them would be paid work for nothing. Only the
      # stable-named files can be stale. The first 1000 paths per month are free; /* would
      # also throw away every cached HLS segment under /processed/, which is the expensive
      # part of the cache and has nothing to do with a web deploy.
      - name: Invalidate only the paths that can be stale
        working-directory: ${{ env.TF_DIR }}
        run: |
          set -euo pipefail
          DIST="$(terraform output -raw cloudfront_distribution_id)"
          aws cloudfront create-invalidation --distribution-id "$DIST" \
            --paths / /index.html /favicon.svg /icons.svg \
            --query 'Invalidation.[Id,Status]' --output text

      - name: Print the deployed entry point
        working-directory: ${{ env.TF_DIR }}
        run: |
          set -euo pipefail
          APP="$(terraform output -raw app_url)"
          echo "app:      $APP"
          echo "api:      $APP/videos"
          echo "playback: $APP/processed/{id}/master.m3u8"
```

Every action is pinned to an exact release tag, no floating major: `actions/checkout@v7.0.1`, `actions/setup-go@v7.0.0`, `actions/setup-node@v7.0.0`, `pnpm/action-setup@v6.0.9`, `hashicorp/setup-terraform@v4.0.1`, `aws-actions/configure-aws-credentials@v6.2.3`, `aws-actions/amazon-ecr-login@v2.1.6`. Pinning to a SHA is stricter still; the tags above are the trade-off this repo takes, and a bump is a reviewable one-line commit.
